# ClickFlow 设计规格

**日期：** 2026-09-30  
**状态：** 已批准，可实施
**目标平台：** Windows 10/11 x64  
**实现语言：** C17

## 1. 产品目标

ClickFlow 是一款轻量、离线、无需登录的 Windows 鼠标自动化工具。它提供鼠标连点、鼠标录制回放和可视化宏编辑，同时保持安装简单、界面克制、运行状态清晰。

第一版不包含联网、账号、会员、任意 Lua/JavaScript 执行、图片识别或后台窗口点击。用户必须主动启动每一项输入任务，并能随时通过全局热键或紧急停止键终止任务。

## 2. 成功标准

- 使用 CMake 和 Ninja 构建 Debug、Release 版本。
- 使用 GCC 15.2 编译时，项目自身代码不产生编译警告。
- Release 主程序无需安装即可运行，并发布为单个 EXE；许可证和使用说明作为独立文档随包分发。
- 连点、录制和宏任务在其他应用位于前台时仍可通过全局热键控制。
- 启动或停止操作在正常系统负载下于约 100 毫秒内给出界面反馈。
- 连续运行一小时后没有持续内存增长、残留钩子或残留工作线程。
- 125%、150% 和 200% DPI 下界面清晰，控件不重叠。
- 热键冲突、非法参数、坐标越界、文件损坏和输入发送失败均显示明确的中文错误。

## 3. 第一版功能范围

### 3.1 鼠标连点

- 鼠标左键、中键和右键。
- 单击或双击。
- 以整数毫秒设置点击间隔。
- 支持持续运行、指定点击次数和指定持续时间三种停止条件。
- 支持在当前光标位置点击或在固定物理屏幕坐标点击。
- 支持用户设置的全局启停热键。
- 显示就绪、运行、暂停、停止和错误状态。
- 启动前校验间隔、次数、持续时间、热键和固定坐标。
- 点击间隔范围为 1–2,592,000,000 毫秒，指定点击次数范围为 1–1,000,000,000 次，指定持续时间范围为 1–2,592,000,000 毫秒。

### 3.2 鼠标录制

- 录制鼠标移动、按下、松开、点击和滚轮。
- 支持开始、暂停、继续和停止录制。
- 支持回放、暂停、继续和停止回放。
- 支持调整回放速度和整个录制的重复次数。
- 支持保存、重命名、删除、导入和导出录制。
- 录制完成后生成与宏编辑器共用的动作列表。

### 3.3 可视化宏

- 支持移动、按下、松开、点击、滚轮和等待动作。
- 支持新增、删除、复制、编辑和调整动作顺序。
- 支持设置整个动作列表的重复次数与播放速度。
- 支持为每个宏配置独立全局热键。
- 支持保存、重命名、删除、导入和导出宏。
- 第一版不支持嵌套循环；重复仅作用于整个动作列表。

### 3.4 设置

- 深色和浅色主题，默认使用深色主题。
- 配置默认连点参数、全局启停热键和紧急停止键。
- 紧急停止键默认是 `Esc`，始终保留可用，但允许用户改为其他不冲突的全局热键。
- 自动保存已通过校验的配置。
- 单实例运行；第二次启动时激活已有窗口。

## 4. 视觉与交互设计

主窗口基准尺寸为 820 × 560 逻辑像素，并支持 Windows DPI 缩放。窗口采用左侧窄导航栏和右侧内容区域，导航包含连点、录制、宏和设置四项。

界面使用石墨黑、雾白和低饱和灰作为基础颜色，翡翠绿仅表示运行状态与主要操作。字体优先使用“Microsoft YaHei UI”，缺失时回退到“Segoe UI”。控件圆角为 6–10 像素，使用轻微阴影和充足留白，不使用大面积高饱和色、渐变背景或装饰纹理。

主区域遵循固定信息层级：顶部显示页面标题和任务状态，中部以少量卡片组织参数，底部提供清晰的主操作按钮。连点页依次展示点击方式、执行规则和启动控制。录制页与宏页复用同样的间距、卡片和状态样式。

热键输入控件在点击后进入捕获状态，用户直接按组合键完成设置。任务运行时，主按钮切换为“停止”，状态颜色和文本同步变化。页面切换和状态变化可使用 100–180 毫秒的轻量动画，但动画不得阻塞输入或延迟停止操作。

## 5. 技术方案

### 5.1 技术栈

- C17。
- Win32 API：窗口、消息循环、全局热键、单实例和系统集成。
- Nuklear：即时模式界面与主题绘制。
- Nuklear Win32/Direct3D 11 后端：渲染和输入桥接。
- Win32 `SendInput`：前台鼠标输入模拟。
- Win32 低级鼠标钩子：鼠标录制。
- cJSON：配置、录制和宏的 JSON 解析与序列化。
- CMake 4.x、Ninja 和 MinGW-w64 GCC 15.2。
- CTest 和项目内轻量测试入口，不额外引入单元测试框架。

Nuklear 与 cJSON 源码随项目固定版本存放，并保留各自许可证。Release 构建静态链接 MinGW 运行库，目标是生成一个主程序文件。

### 5.2 模块边界

| 模块 | 职责 | 主要依赖 |
| --- | --- | --- |
| App | 窗口、消息循环、DPI、主题、页面切换 | Win32、Nuklear |
| Controller | 任务互斥、状态机、启动和停止协调 | Clicker、Recorder、Macro、Hotkey |
| Clicker | 校验并执行连点任务 | Input、Clock |
| Recorder | 采集鼠标事件并生成动作 | Win32 hook、Action queue |
| Macro | 动作列表编辑、校验和执行 | Input、Clock、Storage |
| Input | 封装并校验 `SendInput` 调用 | Win32 |
| Hotkey | 注册、注销和检测全局热键冲突 | Win32 |
| Storage | 原子保存与加载配置、录制和宏 | cJSON、Win32 filesystem |
| Diagnostics | 本地日志、用户可读错误信息 | Win32 filesystem |

界面不直接调用 `SendInput`、鼠标钩子或文件解析。所有任务通过 Controller 启动，Controller 保证连点、录制和宏三种活动互斥。

## 6. 线程与状态模型

UI 始终运行在主线程。连点和宏共用一个执行线程，同一时间最多运行一个任务。录制使用独立的消息线程安装低级鼠标钩子；钩子回调只记录时间戳并向有界队列写入事件，不执行文件操作或界面更新。

执行线程在启动时获取不可变的任务参数副本。界面对表单的后续修改不会影响正在运行的任务。任务状态使用以下有限状态机：

```text
IDLE -> STARTING -> RUNNING <-> PAUSED -> STOPPING -> IDLE
                         \-> ERROR -> STOPPING
```

停止信号使用 Windows event。等待实现必须能被停止事件打断，不能通过不可中断的长时间 `Sleep` 完成。窗口关闭时，Controller 依次发出停止信号、等待线程结束、卸载钩子、注销热键、保存有效配置，然后销毁窗口。

## 7. 动作模型与执行规则

录制和宏共享扁平动作列表。核心类型为：

```c
typedef enum ActionType {
    ACTION_MOVE,
    ACTION_BUTTON_DOWN,
    ACTION_BUTTON_UP,
    ACTION_CLICK,
    ACTION_WHEEL,
    ACTION_WAIT
} ActionType;
```

每个动作包含动作类型、相对前一动作的等待毫秒数，以及该类型所需的坐标、鼠标键或滚轮量。无关字段在内存中置零，序列化时省略。动作列表执行前必须校验：动作类型已知、等待时间合法、鼠标键合法、坐标位于当前虚拟桌面，以及按下和松开序列不会留下未释放按钮。

坐标采用进程 DPI 感知后的虚拟桌面物理像素。录制文件保留录制时的虚拟桌面边界；当前屏幕布局与记录不兼容时，回放前显示错误并拒绝启动。

单个动作的等待时间范围为 0–2,592,000,000 毫秒。播放速度范围为 0.1–10.0，执行时通过缩放等待时间生效，不修改原始动作。重复次数范围为 1–1,000,000；界面另外提供“持续运行”选项，该选项只存在于运行参数中，不以无限整数写入文件。

## 8. 数据格式与存储

程序数据目录为 `%LOCALAPPDATA%\ClickFlow`：

- `config.json`：用户配置。
- `logs\latest.log`：当前诊断日志。
- `backups\`：损坏配置和保存失败前的备份。

录制和宏由用户选择保存位置。文件扩展名分别为 `.cfr.json` 和 `.cfm.json`，两者都使用 UTF-8 JSON，并包含 `schema_version`。第一版 schema 版本为 1。

宏文件示例：

```json
{
  "schema_version": 1,
  "kind": "macro",
  "name": "示例宏",
  "repeat_count": 3,
  "playback_speed": 1.0,
  "recorded_virtual_screen": {
    "left": 0,
    "top": 0,
    "width": 1920,
    "height": 1080
  },
  "actions": [
    { "type": "move", "x": 820, "y": 460, "delay_ms": 0 },
    { "type": "click", "button": "left", "delay_ms": 120 },
    { "type": "wheel", "delta": -120, "delay_ms": 300 }
  ]
}
```

Storage 先将 JSON 写入同目录临时文件，刷新并关闭文件后再替换目标文件。解析失败时不得覆盖原文件。配置损坏时将其移动到 `backups`，记录原因，并加载内置默认配置。

## 9. 错误处理与安全停止

- 热键注册失败或发生冲突时拒绝保存，并显示冲突对象。
- 连点间隔、次数、持续时间、播放速度、重复次数和坐标在启动前统一校验。
- 固定坐标或动作坐标超出当前虚拟桌面时拒绝启动。
- `SendInput` 返回的事件数少于请求数时立即进入错误状态并停止任务。
- 单个导入文件最大 64 MiB，单个录制或宏最多包含 1,000,000 个动作；超过限制时拒绝加载，防止损坏文件耗尽内存。
- 所有动作列表使用带容量检查的动态数组；整数换算前检查溢出。
- 任务停止或异常退出时，Input 模块释放由 ClickFlow 按下但尚未释放的鼠标按钮。
- 日志只记录程序状态、错误码和文件路径，不记录用户点击内容或其他应用文本。
- 程序默认不自动执行任何输入任务，也不在系统启动时自动运行。

## 10. 测试策略

核心模块不依赖窗口即可测试。自动测试覆盖：

- 连点参数边界、停止条件和任务状态转换。
- 热键组合规范化与冲突检测中的纯逻辑部分。
- 动作列表校验，包括未知动作、非法按钮、坐标越界、超大等待和未配对按下。
- JSON 正常读取、未知 schema、截断文件、超限文件和保存后往返一致性。
- 播放速度换算、重复次数和可中断等待。
- 录制事件转动作、连续移动压缩和点击组合。
- 停止信号到达后不再发送新输入。

手动 Windows 验收覆盖：

- 连点、录制、回放和宏的完整用户路径。
- 在其他普通桌面应用位于前台时使用全局热键。
- 多显示器及不同排列方式。
- 125%、150% 和 200% DPI。
- 热键冲突、坐标越界、文件损坏、只读目录和磁盘写入失败。
- 一小时连续连点与重复宏，观察内存、CPU、句柄和停止响应。
- 任务运行期间正常关闭和系统注销。

测试不会自动向用户当前桌面发送真实点击。Input 模块通过函数接口注入测试替身；真实输入只在明确的手动验收步骤中启用。

## 11. 发布约束

- 支持 Windows 10 和 Windows 11 x64。
- 不需要管理员权限。
- 不写注册表，不安装服务，不添加开机启动项。
- 不联网，不收集遥测，不包含账号或付费功能。
- 分发包包含单个 EXE 主程序、第三方许可证和简短使用说明；全部非系统依赖静态链接进主程序。

## 12. 明确不在第一版中的功能

- 后台窗口点击与后台窗口录制。
- 图片识别、OCR 和基于画面的条件执行。
- 任意 Lua、JavaScript 或其他脚本语言执行。
- 嵌套循环、条件分支、变量和跨宏调用。
- 键盘输入录制与键盘宏。
- 云同步、宏市场、账号、会员和在线更新。
- 绕过游戏反作弊、软件输入限制或系统安全机制。

这些功能只有在第一版稳定后，经过单独设计和风险评估才会进入后续版本。
